# RSA Demo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A keyboard-driven, 9-step animated web demo in which a marine, a Cyberdemon and an imp explain RSA key setup, encryption, decryption and why it works, using small numbers, deployed on Vercel.

**Architecture:** A Next.js static export renders one full-screen page. A Rust crate compiled to WebAssembly provides the RSA math behind a small TypeScript `RsaEngine` interface, with a pure-JS implementation of the same interface as automatic fallback. A pure `buildSteps(engine)` function turns the engine's results into 9 step definitions (equation text plus scene state); a canvas stage draws the three characters from that scene state and an equation strip shows the math.

**Tech Stack:** Next.js (App Router, `output: "export"`), TypeScript, React, Vitest, Rust + `wasm-bindgen` + `wasm-pack`, HTML canvas, Vercel.

**Spec:** `docs/superpowers/specs/2026-11-03-rsa-demo-design.md`

## Global Constraints

- Demo numbers are fixed: **p = 3, q = 11, n = 33, φ(n) = 20, e = 3, d = 7, m = 4, c = 31**.
- Layout A: characters large on a stage across the top, a strip below holding the current equation, a step-progress bar with the arrow-key hint at the bottom.
- 9 steps, advanced only by key press, never automatically: `→` / `PageDown` forward, `←` / `PageUp` back.
- Slot is about 10 minutes. Text must be readable from the back of a classroom (large type, high contrast).
- Characters use the owner-supplied sprite sheets `Marine.png`, `Imp.png`, `Cyber Demon.png` (project root; moved to `public/sprites/` in Task 4), labeled "Marine", "Cyberdemon", "Imp", with a visible credit line "Sprites ripped by Falcon Delta; Doom is a trademark of id Software/Bethesda" (see spec, Constraints).
- English text only.
- Static export on Vercel with the owner's domain. The built site must also run locally from a static folder as a backup.
- Rust to WebAssembly engine, plus a plain-JS fallback implementing the same math. Not a real cryptography library: no padding, no big-number support.
- The real-size cracking timer in step 4 is a clearly labeled estimate, not a computation. Only n = 33 is factored for real.
- No backend, database, accounts or analytics.

## Review Focus

1. WebAssembly fails to load (blocked, offline, wrong MIME type, opened from `file://`): the demo must silently use the JS engine and look identical. Pinned in Task 2.
2. Presenter holds a key, or presses `→` on the last step or `←` on the first: no skipped steps, no crash, no negative index. Pinned in Task 3.
3. Projector at a different resolution or aspect ratio (1280×720, 1024×768): nothing is clipped, text stays readable. Pinned in Task 4.
4. Engine inputs outside the happy path: `m >= n`, `e` not coprime to φ, `p` or `q` not prime, `modulus = 1`. Pinned in Tasks 1 and 2.
5. Presenter pushes the browser to fullscreen or resizes the window mid-demo: the stage re-fits without losing the current step. Pinned in Task 4 (`fitScale` test and the manual check in step 6).

### Task 1: Engine interface, test vectors, JS fallback engine

**Files:**

**Interfaces:**
- Produces:
  ```ts
  export interface RsaEngine {
    readonly kind: "wasm" | "js";
    isPrime(n: number): boolean;
    gcd(a: number, b: number): number;
    phi(p: number, q: number): number;                 // (p-1)(q-1); throws RangeError unless p, q prime and p != q
    smallestFactor(n: number): number;                 // smallest factor > 1, n itself if prime; n >= 2
    modPow(base: number, exp: number, modulus: number): number;   // modulus >= 1
    modInverse(a: number, modulus: number): number | null;        // null when gcd(a, modulus) != 1
    encrypt(m: number, e: number, n: number): number;  // throws RangeError unless 0 <= m < n
    decrypt(c: number, d: number, n: number): number;  // throws RangeError unless 0 <= c < n
    powerCycle(base: number, modulus: number): number[]; // [1, base, base^2, ...] mod modulus until it returns to 1
  }
  export function createJsEngine(): RsaEngine;
  ```
- `shared/engine-vectors.json` is an array of `{ "fn": string, "args": number[], "expect"?: number | boolean | null | number[], "throws"?: true }`. Both engines' tests read it.
